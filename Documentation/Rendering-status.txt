性能数据的含义
  20,000 音符的 600 次可见查询属于索引性能，不是完整画面 FPS。
  窗口内“刷新 Hz/超时”统计来自 DisplayLink 回调；超时是间隔超过目标 1.6 倍。
  它不是 GPU 完成帧率，也不是专业输入延迟测试。不能因此保证所有设备稳定 120。
  已将传感器文字缓存成图像，并减少时间轴全谱重画和刷新回调重复配置。
  120 Hz 的大尺寸双窗口预览曾观察到 69 Hz/每秒 26 次超时；尚不能保证稳定
  120。60 Hz 独立舞台在结尾段采样显示 60 Hz/0 次超时。此为窗口回调采样。

0.3.6 音频时钟连续性
  AVAudioPlayerNode 的时间戳按音频块更新，直接用于 120 Hz 画面会产生相同时间的
  重复帧。现在在同一 host clock 内插值，每个音频块重新校准；未来 host time 保留
  负时间差，正确处理预定播放、暂停、回拖、结束和变速，不用墙上时钟累计漂移。
  实际静音引擎测试中，120 次读取有 87 次底层样本时间相同，插值时间在这 87 次
  均继续推进。三项时钟测试和固定刷新范围测试通过；共 76 项。
  0.3.6 用户正常播放的宽屏窗口在 01:13.822 读到 120 Hz / 0 次超时；这是单个窗口
  读数，且用户已选 Classic、关闭按压高亮，不能与上面的区域模拟实验作严格对照。

0.3.7 导出路径
  导出复用 ImageRenderer 视图图谱；CGImage 输出保持 Canvas GPU 绘制。实测直接
  render(rasterizationScale:renderer:) 到 CGContext 会明显变慢，因此没有采用该路径。
  PV 使用 AVAssetReaderTrackOutput 连续解码，alwaysCopiesSampleData=false，NV12
  输入经 Metal-backed CIContext 转换/缩放；按源时间戳复用帧，修正 track transform
  与 Core Image 坐标方向差异。输出维持原 H.264/AAC、60 fps、像素尺寸和码率。
  编码缓冲池为 IOSurface-backed BGRA；仍需将 SwiftUI 图像送入编码缓冲区，尚未
  实现整个舞台的独立 Metal 渲染或纹理直通编码，不能称为全流程零拷贝。

  同机短片对照：[DX] 系ぎて Re:MASTER 55–57 秒，120 帧，所有特效、区域显示、
  宽屏统计开启，无采样器。计时不包含音频混合/AAC/最终封装。
    原路径 1280×720：无 PV 0.904 秒，PV 2.225 秒。
    新路径 1280×720：无 PV 0.368 秒，PV 0.551 秒。
    原路径 1920×1080：无 PV 0.909 秒，PV 2.388 秒。
    新路径 1920×1080：无 PV 0.490 秒，PV 0.656 秒。
    1080p PV 取帧耗时 1.408 → 0.109 秒。一次短片实验约 3.6 倍，非所有曲目的保证。
  四个覆盖音符、烟花、长押、区域和完整侧栏的对照帧像素完全一致；PV 色彩转换
  和旋转测试平均通道差约 1.8–1.95 / 255，属于不同解码/颜色转换路径的小幅差异。

0.3.8 时间轴文字崩溃修复
  用户在 0.3.7 build 11 打开独立宽屏舞台时崩溃。报告指向主线程
  TimelineCanvas.cursor -> NSString.size(withAttributes:) -> CoreText TAttributes::ApplyFont，
  字典复制抛出 NSInvalidArgumentException（nil object）；不是 Metal/视频导出调用栈。
  不能仅凭调用栈确定系统内部哪一个字体属性变为 nil，也没有稳定复现原版异常。
  现在移除时间轴全部 NSString 属性测量/绘制调用，使用初始化时建立的具体 Menlo
  Regular/Bold CTFont、预缓存字形与 advance，直接 CTFontDrawGlyphs。原有信息保留。
  时间轴播放时间和坐标加入 finite 检查，避免异常值进入 Int 格式化和 Core Graphics。
  60,000 次原生 draw/cacheDisplay，切换明暗主题、720/420 宽度、4×/1×缩放、3/4 拍
  和源码位置，通过；300 次背景重建，播放光标持续更新。另检查 NaN/Infinity 时间。
  14 组文字度量与 Core Text 标准行布局一致、绘制像素一致（含 U+2212 负号）。
  83 项回归通过，日志 validation-0.3.8-log.txt 与 validation-0.3.8-timeline-log.txt。
  这属于针对已定位崩溃入口的修复，压力测试不能证明今后不会出现其他偶发问题。
